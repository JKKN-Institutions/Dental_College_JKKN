3. Mobile LCP 6.5s — hero image is a heavy JPG

P1

Mobile performance 69/100 (desktop is 96)

· Effort: 1–2 hrs
components/Hero.tsx  — lines 77–84 (the <Image> render)
⚠️ Important — already done, don't redo: The hero <Image> already has priority and a correct sizes attribute. The problem is not a missing priority flag. The problem is the image format and weight.
Root causes (from PageSpeed mobile)
  • LCP element = hero image /images/JKKN-Dental-Clinical-Training.jpg — served as JPG only (no WebP/AVIF variant exists in public/images/).
  • ≈ 880ms of unused JavaScript and ≈150ms unused CSS on first load.
  • Mobile LCP = 6.5s vs target < 2.5s. Google crawls this page as mobile, so this is the figure that affects ranking.
Fix steps
  1. Serve modern formats. Confirm next.config.ts has: 
    images: { formats: ['image/avif', 'image/webp'] }
    With this, Next.js auto-serves AVIF/WebP from the existing JPG. If the JPG source is very large, also export a compressed/resized master (target the rendered display size, ~1200px wide max for the hero).
  2. Add explicit width/height (or keep fill with a sized container) so the browser reserves space — prevents layout shift and helps LCP.
  3. Cut unused JS (880ms). The page already uses dynamic() for below-the-fold sections (good). The remaining unused JS is most likely third-party (GTM / Analytics). Load those with strategy="afterInteractive" or "lazyOnload" via next/script in app/layout.tsx.
✔ Verify: Run PageSpeed Insights (mobile) on the homepage. Target: LCP < 2.5s, Performance > 90. Confirm DevTools → Network shows the hero served as .avif or .webp.

6. Event schema missing 3 fields

P3

Admissions Event JSON-LD incomplete

· Effort: 10 min
app/page.tsx  — locate the JSON-LD block with "@type": "Event"
Google flags the Event as missing performer, price, and priceCurrency. Adding them unlocks the full Event rich result.
Add these fields to the Event object
{
  "@type": "Event",
  // ...existing name, startDate, location...
  "performer": { "@type": "Organization", "name": "JKKN Dental College & Hospital" },
  "offers": {
    "@type": "Offer",
    "price": "0",
    "priceCurrency": "INR",
    "availability": "https://schema.org/InStock",
    "url": "https://dental.jkkn.ac.in/admission/"
  }
}

(If admission enquiry is free, price: "0" is correct. Use the real application fee if there is one.)

✔ Verify: Google Rich Results Test on the homepage → Event shows 0 errors/warnings.

7. Missing X-XSS-Protection header

P3

Minor security-header gap

· Effort: 5 min
next.config.ts  — inside headers() for source /(.*)
Add this header to the existing array

Modern guidance is X-XSS-Protection: 0 (the legacy filter is deprecated; your CSP does the real protection). Some scanners still want the header present. Don't remove your existing CSP / HSTS / X-Frame-Options.
